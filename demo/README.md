# The public replay demo

**Published at <https://ajaffer.github.io/interview-signals.html>**
(source: `ajaffer/ajaffer.github.io` → `interview-signals.html`).

`index.html` is the portfolio artifact: a single self-contained file that replays a
recorded session — transcript filling in, phase changing, signal cards appearing and
ageing out, and every suppressed judgment listed with the reason it was withheld.

It makes **no API calls**. Drop it anywhere static (GitHub Pages, S3, a file:// path) and
it works, forever, for free.

## Rebuild it

Two commands. The first produces a session with real Jev decisions; the second renders it.

```bash
# 1. Replay a transcript through real Jev into a throwaway database.
./.venv/bin/mis replay transcripts/fixtures/sample-001-url-shortener.jsonl \
  --adapter typesafe --db /tmp/demo.db --tick-ms 15000

# 2. Render that session into demo/index.html (session id is printed by step 1;
#    a prefix is enough).
./.venv/bin/python demo/build_demo.py /tmp/demo.db <session-id>
```

Step 1 prints the session id on its first line and costs a cent or two. Step 2 is free and
offline. Check the result with `open demo/index.html`.

`--tick-ms 15000` on a 10-minute transcript gives about 40 evaluation ticks, which is
enough signal density to watch. Raising it thins the strip out; lowering it costs more.

## Use the synthetic fixture, not a real session

`build_demo.py` will happily render any session in any database, including a live one from
`sessions.db`. **Do not publish one.**

Real sessions are identifiable people who agreed to a mock interview, not to being posted
on the internet. The project's rule is explicit consent before anything involving a peer,
and a public portfolio page is the worst possible case for that.

`transcripts/fixtures/sample-001-url-shortener.jsonl` is hand-written and contains no real
person. It was built to exercise all five signals — including a deliberately unanswered
question and a rambling stretch — so it demos better than a real session anyway. The
decisions rendered over it are real Jev output, and the page's footer says exactly that.

If you ever do want a real session on a public page, get written consent from the other
person first, and anonymize the transcript before rendering.

## Editing the page

`template.html` is the source; `index.html` is generated and will be overwritten. Edit the
template, then rerun step 2. The session JSON is injected in place of the
`/*__SESSION__*/null` marker, so the built page has no external dependencies at all.

## Deploying, and the copy that is already live

The published page is **not** a copy of `index.html`. It was integrated into the portfolio
site: styles scoped under `.demo`, the site's own `style.css` pulled in, the dark-mode
palette dropped for a light-only one, and a full-bleed wrapper. That work lives in the
Pages repo and should stay there.

So there are two files and they diverge on purpose:

| | `demo/index.html` | `interview-signals.html` |
|---|---|---|
| Owns | the standalone demo | the published page |
| Styling | self-contained, light + dark | scoped to `.demo`, uses `style.css` |
| Regenerated by | `build_demo.py` (overwrites) | `build_demo.py --into` (data only) |

**Never copy `index.html` over the published page** — it would wipe the site integration.
To refresh the published page with a new session, swap only the data:

```bash
./.venv/bin/python demo/build_demo.py /tmp/demo.db <session-id> \
  --into ../ajaffer.github.io/interview-signals.html
```

That rewrites the single `const SESSION = ...;` line and leaves every rule, link and
wrapper untouched. Verify with `git diff` in the Pages repo: exactly one line should
change.

## Why it replays instead of calling Jev live

The TypeSafe API runs an origin allowlist. A preflight from an unlisted origin is answered
`400 Disallowed CORS origin`, and a POST carrying JSON plus an `Authorization` header is
not a simple request, so a browser preflights it and the call never leaves the page. A
static site therefore cannot reach Jev.

That is the right outcome anyway: reaching it would mean an API key in public JavaScript.
Replaying a recorded session gives real answers, real latencies and the real suppression
rate with no key, no backend and no running cost. See [`spike/jev-cors/`](../spike/jev-cors/)
for what an *extension* can do, which is a different question with a different answer.

## Two fixes that came back from the published copy

The site integration found a real bug and added a feature; both are now in
`template.html`, so a rebuild keeps them.

- **Non-numeric values rendered as `NaN`.** The suppressed feed formatted every value as a
  number, but a suppressed `current_phase` row carries a label, not a number. 31 of the
  111 suppressed rows in the sample session showed `current_phase NaN`. Fixed by falling
  back to the label text.
- **A running cost tile.** Jev bills input tokens only, at
  [$0.042 per million, output free](https://docs.typesafe.ai/models). Every signal in a
  tick rides one batched request and carries that request's token count, so the tally bills
  each window once rather than once per answer. The sample session totals **0.25¢ over 39
  calls** — which is the number that makes the whole approach look reasonable, so it earns
  its place on the page.
